# ЕдуТест (edu-assess)

Платформа за създаване на тестове, класни стаи, възлагане на задания и изпити и анализ на резултатите. Интерфейсът е на български; предвидена е за свързване с външна SSO система (без регистрации).

Вдъхновена е от функциите на съвременните платформи за тестове (типове задачи, класни стаи, строг режим на решаване, анализ), но е изградена самостоятелно и без връзки към външни платформи.

## Възможности

- **Демо вход** – 18 демо потребители: 3 учители (Математика, История и цивилизации, Български език и литература) и 15 ученици в три класа (7а, 8б, 12в). Входът е от страницата `/login`; в реална среда ще се замени със SSO (виж по-долу).
- **Класове** – учителят създава класни стаи и добавя/премахва ученици в тях.
- **15 типа задачи** – един верен отговор, повече от един верен, вярно/грешно, избери в празното поле, попълни празното поле, подреди, свържи, групирай, определяне на величина (числово поле или плъзгач), открий грешките, отворен въпрос, отговор с файл, маркирай и назови (изображение с маркери), четене с разбиране и слушане с разбиране (с подвъпроси). Автоматично оценяване с частичен кредит; отворените въпроси и файловете се проверяват ръчно.
- **Редактор на въпроси** – Quill за условието (с бутон за формула), KaTeX за формулите навсякъде (`$x^2$` в опциите и текстовете), качване на изображения и аудио.
- **Банка с въпроси** – лична банка на учителя с филтри; копиране между банката и тестовете.
- **Тестове** – три начина: от нулата, от банката (контейнерите се запълват със случайни въпроси по критерии) или **с AI**.
- **AI генериране (Google Gemini)** – учителят подрежда **контейнери** (тип задача, брой, трудност, теми от учебната програма, указания), а Gemini ги запълва със съдържание, базирано на учебната програма, която се подава на модела като контекст. Отделен въпрос може да се „прегенерира“. Без API ключ платформата работи в демо режим (`AI_MOCK=1`).
- **Учебни програми** – структурирани JSON програми в `data/curricula/` (Математика VIII, История VII, БЕЛ XII). Нови се качват от страницата „Учебни програми“.
- **Задания** – възлагане на класове с период, време за решаване, брой опити, варианти, разбъркване, скала за оценяване (2–6) и кога ученикът вижда резултата.
- **Изпитен режим (строг)** – тестът се решава на цял екран; превключване на таб/прозорец, загуба на фокус, излизане от цял екран и забранени клавишни комбинации се отчитат на сървъра. След N предупреждения (по подразбиране 3) следващото нарушение **анулира теста с оценка Слаб (2)**. Отговорите се записват автоматично; времето се контролира и от сървъра.
- **Резултати и анализ** – по задание: предадени/в процес/незапочнали, среден успех и оценка, разпределение на оценките, успеваемост по всеки въпрос (най-трудните въпроси), таблица по ученици с брой предупреждения; преглед на всяко решение с дневник на опита; ръчно оценяване и коментари. Ученикът вижда своите резултати и верните отговори (ако учителят е разрешил).
- **Печат** – тестът и отделен документ с отговорите (`/tests/{id}/print?key=1`).

## Технологии

- Python **3.12.11**, [uv](https://docs.astral.sh/uv/), **FastAPI**, SQLAlchemy 2, Jinja2
- **SQLite** в WAL режим, настроен за много едновременни потребители (виж по-долу)
- Фронтенд без build стъпка: vanilla JS модули, **Quill 2**, **KaTeX**, икони **Lucide** (всичко е локално в `app/static/vendor` – работи и без интернет)

## Стартиране

```bash
uv sync                       # инсталира Python 3.12.11 (ако липсва) и зависимостите
cp .env.example .env          # по желание: GEMINI_API_KEY, SECRET_KEY …
./run.sh                      # http://localhost:8000
```

`run.sh` стартира uvicorn с `WEB_CONCURRENCY` работни процеса (по подразбиране **2**) и `WORKER_THREADS` нишки на процес (по подразбиране 40). При първо стартиране базата се създава в `data/db/` и се зареждат демо данните.

Алтернативно: `uv run uvicorn app.main:app --workers 2 --port 8000` или `docker build -t edu-assess . && docker run -p 8000:8000 -v edu_data:/app/data edu-assess`.

API документация: `http://localhost:8000/api/docs`.

### Променливи на средата (`.env`)

| Променлива | Описание |
|---|---|
| `SECRET_KEY` | ключ за подписване на сесиите (задължително сменете) |
| `WEB_CONCURRENCY` | брой работни процеси (по подразбиране 2) |
| `WORKER_THREADS` | нишки за синхронни операции на процес (40) |
| `DB_POOL_SIZE`, `DB_BUSY_TIMEOUT_MS` | пул и изчакване при заключена база |
| `GEMINI_API_KEY`, `GEMINI_MODEL` | Google Gemini (по подразбиране `gemini-2.5-flash`) |
| `AI_MOCK` | `1` = демо генериране без реален AI (когато няма ключ) |
| `MAX_UPLOAD_MB` | максимален размер на качван файл |
| `DATABASE_PATH`, `UPLOADS_DIR` | пътища (по подразбиране в `data/`) |

## Как е решено натоварването

- **Няколко процеса** (`WEB_CONCURRENCY`) + **thread pool** за синхронните крайни точки: FastAPI изпълнява `def` функциите в нишки, така че event loop-ът не се блокира от SQLite. Лимитът на нишките е вдигнат на `WORKER_THREADS`.
- **SQLite WAL** – четенията не блокират записите; `synchronous=NORMAL`, `busy_timeout`, `mmap`, голям cache.
- **Сесии за запис с `BEGIN IMMEDIATE`** (`app/db.py: get_db_write`) – записващите транзакции вземат lock веднага и не се стига до взаимни блокировки при повишаване от четене към запис. Транзакциите са кратки (автоматичният запис на отговор е един UPSERT).
- Извикванията към Gemini са **асинхронни** (httpx) и не заемат нишки; базата се пипа само преди и след тях.
- **Междупроцесен lock** при стартиране – само един процес създава таблиците и зарежда демо данните.
- Индекси по всички външни ключове и често използвани комбинации.

Тест за натоварване (15 ученици едновременно записват отговори и предават):

```bash
uv run python scripts/loadtest.py --students 15 --rounds 60
```

## Структура

```
app/
  main.py            FastAPI приложение, middleware, стартиране
  config.py          настройки от средата
  db.py              SQLite/SQLAlchemy – WAL, IMMEDIATE транзакции, startup lock
  models.py          ORM модели (потребители, класове, тестове, въпроси, задания, опити, отговори, събития)
  question_types.py  регистър на 15-те типа въпроси: валидация, публични данни, описание за AI
  grading.py         автоматично оценяване и скала 2–6
  services.py        подредба на опит, оценяване на опит, нарушения, статистики
  seed.py            демо потребители, класове, примерни тестове и задания
  curricula.py       зареждане на учебните програми и контекст за AI
  ai/gemini.py       Gemini клиент (JSON отговор), демо генератор
  routers/           API (classes, questions, tests, assignments, attempts, uploads, curricula) и HTML страници
  templates/         Jinja2 шаблони (учител / ученик)
  static/            app.css, js модули (questions.js – рендер на всички типове; player.js – решаване и изпитен режим; editor.js – редактор; builder.js – конструктор с контейнери), vendor (Quill, KaTeX, Lucide)
data/curricula/      учебни програми (JSON)
scripts/loadtest.py  тест за натоварване
tests/               pytest
```

## Формат на учебна програма (JSON)

Минимално: `subject`, `grade` (напр. `"VIII клас"`) и `topics` – списък с `title`, `results` (очаквани резултати) и `concepts` (нови понятия). По желание: `scope`, `goals`, `subtopics`, `formulas`, `end_results`, `assessment`, `code`, `grade_number`. Виж `data/curricula/math-8.json`.

## SSO (предстои)

Няма регистрации. Потребителите се създават/намират по `User.external_id`, а входът става с `app/auth.py: login_user()`. Заготовката е в `app/routers/pages.py: sso_callback` – там ще се проверява токенът на външната система и ще се извиква `login_user()`. Демо входът (`/login`) остава за разработка.

## Бъдещи надграждания (извън тази основа)
